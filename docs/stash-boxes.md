# 两种收纳盒

一个分类就是一只盒子。**收纳 = 把文件真的搬进这个盒子**（像资源管理器里拖文件夹），
种类只决定「搬去哪儿」和「之后跟不跟磁盘同步」。现在只有两种：**普通盒**与**映射盒**。

## 两种语义

| | 普通收纳盒 `shortcut` | 映射收纳盒 `mapped` |
|---|---|---|
| 加什么 | 文件 / 文件夹 / `.lnk` / 网址 | 直接指向一个真实文件夹 |
| 拖入 | **移动**进 `<数据目录>/<盒子路径>` | **移动**进绑定的真实文件夹，扫描后出现在盒子里 |
| 条目来自 | 手动加、拖入（移动） | 目录扫描（`dir` + `syncDir`） |
| 删除条目 | 移出列表（文件进回收站） | 只影响列表，不动磁盘 |
| 典型用途 | 常用网址、桌面图标、资料 | 项目目录、下载目录 |

`storage`（存储盒）是历史取值：那时拖入会搬进 `<数据目录>/stash/<id>/`。现在所有盒子拖入都是移动，
行为一致，所以 `categoryKind()` 把 `storage` 直接归到 `shortcut`（**老数据零迁移**，盒子照常显示为普通盒）。
`categoryKind()` 仍是纯函数：`mapped` 优先，没有 kind 的老数据 `syncDir → mapped`，其余 `shortcut`。

## 新建盒子：先选种类，再填名字

1. 先选种类：普通 / 映射；
2. 映射盒紧接着「选择文件夹」（系统选目录框），选完**名称自动填成文件夹名**，仍可改；
3. 「创建」在映射盒没选文件夹时是禁用的。

映射盒的右键菜单里另有「更改映射文件夹」；改名就是普通的「重命名收纳盒」。

## 拖进 / 拖出

- **拖进来**：一律 `move_fence_entries`（移动，不复制），目标是 `ensureDir(盒子)`；映射盒就是它绑定的目录。
  文件夹、或合计超过阈值的文件，先弹一次确认（文案明说「收纳是移动，不是复制」）。
  阈值在 **设置 → 系统 → 收纳** 里改（`collectConfirmMb`，默认 200 MB，0 = 只对文件夹确认）。
- **拖出去**：条目卡片（以及多选）拖到窗口外，走 Tauri 的 `drag_out` 交给系统 OLE —— 落到桌面上是**真文件**。
  墙上的小预览图标仍是 HTML5 拖拽（只用于盒间调整），但不再写 `text/plain`，所以不会在桌面留下一个 .txt。
- **成功只 toast 一句「收纳成功」**，不再报条数 / 重复 / 跳过；只有真有失败时才报失败条数。

## 存储盒的几个硬约束

1. **落点**：`<数据目录>/stash/<分类id>/`，跟数据目录一起搬走，换机器能带走。
2. **不覆盖**：同名文件依次退到 `name (2).ext`、`name (3).ext`…
3. **跨盘**：`rename` 失败会退化成「复制后删源」，目录递归复制；删不掉源目录会明确报错。
4. **不留半成品**：`stash_import` 先整批校验路径，缺一个就整批失败，不会搬一半。
5. **删除护栏**：`stash_delete` 先把目标规范化，再要求它必须在 `<数据目录>/stash` 之内，
   否则拒绝 —— 这个命令会被前端用数据文件里的路径调用，不能当通用 `rm` 使。
6. **分类 id 会做目录名**，所以只放行 `[A-Za-z0-9_-]`，挡住 `..\\` 这类穿越。

## 怎么用

1. 文件收纳 → 新建收纳盒 → 先选种类（普通 / 映射）
2. 普通：直接填名字；映射：先选文件夹，名称自动填成文件夹名（可改）

## 能力边界

| 操作 | 普通（shortcut） | 映射（mapped） |
| --- | --- | --- |
| 拖图标进/出盒子 | ✅ | ✅（进＝搬进绑定目录） |
| 多选图标 → 新建盒子 | ✅ | ❌ |
| 解散盒子 | ✅ | ✅（只解除映射） |
| 盒子内自由排序 | ✅ | ❌（顺序由目录决定） |

映射盒的内容归磁盘上那个真实目录：删除盒子＝解除映射，文件仍在原处；删除条目＝只移出列表。

## 当前实现状态

- 盒子图标：玻璃方块 + 3×3 图标预览（iOS 文件夹观感）
- 点盒子 → 弹层展开图标网格；点遮罩/✕ 关闭
- 弹层标题栏的三个工具：视图切换（图标/列表）、设置（齿轮）、添加到此盒
- 拖拽进/出、多选新建：见 `docs/dock-refactor-plan.md`

## 只有收纳盒视图

文件收纳页现在**只有收纳盒墙**：分类 chips 收起来了（墙本身就是分类导航，两套并排只会让人不知道该点哪个）。
图标 / 列表的切换放在**盒子浮层标题栏**（齿轮左边两个小图标），点一下就切，不用进外观面板。

| 元素 | 行为 |
| --- | --- |
| 方块 | 每个分类一只，3×3 预览只摆**真实条目**（有什么放什么，最多 9 个），右上角数量徽标 |
| 配色 | **按种类固定**：普通=蓝、映射=橙（`--kind-shortcut` / `--kind-mapped`）；盒面只有一圈品类色描边，种类名在点开后的浮层标题旁只读显示 |
| 点方块 | 原位放大成浮层（iOS 文件夹观感），浮层里是该分类的条目网格 |
| 悬停 ⋯ / 右键 | 同一个分类菜单：新建收纳盒 / 新建（文件夹、文件）/ 重命名收纳盒 / 解散；映射盒多一项「更改映射文件夹」。空白处右键也给「新建收纳盒」 |
| 墙末尾 | 不再放虚线「新建收纳盒」卡片：新建入口在工具栏（**新建收纳盒** / **添加条目**），右对齐 |
| 大小 | 工具栏「小 / 中 / 大」三档（`boxTileSize`，默认中）：方块 84 / 96 / 150px 起；盒内缩略图标 16 / 26 / 40（`ItemIcon` 的 `size` 现在真的落到宽高上） |

### 条目两种展示

| 视图 | 样子 |
| --- | --- |
| 图标（默认） | 桌面图标那样：图标在上、文件名在下居中换行（不省略），类型与标签小胶囊在名字下面 |
| 列表 | 一行一个：20px 图标 + 文件名，类型与标签靠右；行不撑高 |

图标尺寸、字号、是否显示扩展名在盒子外观（齿轮）里调；视图切换在浮层标题栏齿轮左边。

### 桌面上散放的条目

从盒子里拖到「拖到：桌面」、或拖到浮层外的暗色区域，条目会**直接回到墙上**（`categoryId` 置空），
不会自动建一个「桌面」盒。散放条目和盒子**同尺寸、同地位**，按顺序排在墙的末尾：图标无边框、图标占方块的大半，
单击选中（淡蓝底，不是描边）、双击打开、右键是条目菜单；拖到盒子上即归入该盒，拖到另一个散放条目上则在桌面上排序（`moveItemBefore`）。

盒子**删空**会自动解散：最后一条被**删除**后，非映射、无子盒、零条目的盒子直接消失，不弹确认。
只是**移出**（拖到桌面或别的盒子）则保留空盒——用户可能是故意腾空它。

### 盒子之间只有顺序

墙上的盒子可以**拖动排序**（拖过 6px 才算拖，松手插到目标盒子前面，`moveCategoryBefore`），
不能把一个盒子放进另一个盒子：新建弹窗里没有「子盒」，右键菜单里也没有。

深链 `/files?item=<id>` 会自动打开目标所在盒子，否则网格根本不渲染。

空盒子不摆虚线拖放区：整个浮层都是落点，拖动文件时状态行变「松开加入收纳盒」，松手按落点盒子或当前打开的盒子收录。
标题栏按三层排：**标题**（盒子名，15px 半粗）→ **信息**（条目数 · 种类，11px 次要色）→ **工具**（视图切换 / 齿轮 / 添加到此盒 / 收起，靠右成组）。
返回只是左边一个箭头图标（`aria-label` 仍写「返回收纳桌面」），不占一行文字。

从资源管理器拖文件到**空墙**（没有打开盒子、指针也不在任何盒子上）会直接弹「新建收纳盒」并把这次拖入的文件带上：
名字预填第一个文件/文件夹的名字，建完自动打开这个盒子、按它的种类落地。以前这里是原地拒绝（「先打开一个收纳盒」）。

## 没有「默认收纳盒」

以前会在首次使用或拖入文件时自动建一个「默认分类」，现在彻底去掉：

- 首次打开文件收纳页不会自动建盒子；墙是空的，末尾只有「新建收纳盒」
- 页面上的拖入**必须有落点**：没打开盒子时拒绝收集，并提示「先打开一个收纳盒，再把文件拖进来」
  （凭空造一个盒子只会让用户在墙上多出一个不认识的格子）
- 添加条目弹框里**选了收纳盒才加**；没选则确认按钮禁用。没有「不加入」这种显式选项

## 解散（按盒子类型分派）

语义在 `src/features/files/dissolve.ts`，页面与桌面 Dock 共用一套：

| 盒子类型 | 解散时 | 磁盘 |
| --- | --- | --- |
| 映射盒 | 解除映射：盒子与条目从库里消失 | **文件一个都不动** |
| 快捷 / 存储盒 | 条目移到另一个盒子（优先非映射盒） | 文件不动（老存储盒的副本留在 `stash/<旧分类id>/`） |
| 有子分类 | 拒绝：连带删整棵子树不是「解散」该有的意外 | — |

没有别的盒子可接收时，条目从库里移除、文件仍留在原处——不留孤儿条目（它们在任何视图里都看不见）。

菜单里这两项叫「重命名收纳盒」「解散收纳盒」（不叫「重命名分类 / 删除分类」）。映射盒的确认框只写一句：
「只会移除这个盒子和它的镜像条目；绑定的文件夹与里面的文件一个都不动。」

## 条目跨盒移动（拖出 / 拖进）

浮层底部有一条「拖到：」落点条，依次列出桌面、其他盒子（映射盒不作目标）和快捷访问目录。拖卡片时命中就高亮，
松手即搬；拖的是已选中条目就整组搬。没命中落点条则还是盒内重排。

| 目标 | 做什么 |
| --- | --- |
| 快捷访问目录 | 文件真的搬进那个磁盘目录（`move_fence_entries`），条目路径跟着改；网址没有文件，拒绝 |
| 其他盒子 | 只改条目归属，文件留在原处 |
| 映射盒 | 盒间拖拽不接受、也不作为来源；从资源管理器拖进映射盒＝搬进它绑定的目录 |

从资源管理器把文件拖到抽屉里的目录行，只搬磁盘文件，不进库。

## 桌面栅格：全开或全关

工具条右侧一个「桌面栅格」开关（`setAllFencesOnDesktop`）：开就把所有盒子铺到桌面，关就全部收掉。
不再有「这个盒子上桌面、那个不上」的单盒入口 —— 状态行以前那个 `x / y` 计数也一起去掉了。
解散盒子时仍会先关掉它自己的栅栏窗。

显示行为在 **设置 → 系统 → 桌面栅格 → 显示方式** 里全局切换（`fenceReveal`）：

| 方式 | 行为 |
| --- | --- |
| 悬停显示（默认） | 指针离开就淡到 14%，移上去再显形（原「幽灵模式」） |
| 始终显示 | 栅栏一直不透明，适合钉在副屏上盯着的场景 |

栅栏标题栏的「⋯」里不再放单个栅格的幽灵开关 —— 两个来源会互相盖掉。

## 多选

Ctrl/Cmd 挑、Shift 连选、Alt 减选；浮层顶部出工具条，「用选中项新建收纳盒」建完把选中条目搬进去。
**不做盒子嵌套** —— 选中的是条目，盒子本身不参与。映射盒里多选退化成单选。
