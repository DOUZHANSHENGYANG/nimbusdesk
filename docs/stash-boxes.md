# 三种收纳盒

一个分类就是一只盒子，盒子的**种类**决定「拖进来的东西怎么处理」。这是
`FileCategory.kind` 的三个取值，也是 drop / 删除 / 目录同步三处分派的依据。

## 三种语义

| | 快捷收纳盒 `shortcut` | 存储收纳盒 `storage` | 映射收纳盒 `mapped` |
|---|---|---|---|
| 加什么 | 文件 / 文件夹 / `.lnk` / 网址 | 任意格式文件、文件夹 | 直接指向一个真实文件夹 |
| 拖入 | **只记引用**，原文件不动 | **移动**进 `<数据目录>/stash/<分类id>/` | 不搬动；文件夹内容由扫描生成 |
| 条目来自 | 手动加、拖入、剪贴板 | 手动加、拖入（移动） | 目录扫描（`dir` + `syncDir`） |
| 删除条目 | 移出列表（文件进回收站） | 弹确认：连副本一起删 / 只移出列表 | 只影响列表，不动磁盘 |
| 典型用途 | 常用网址、桌面图标 | 收进来的资料（不怕原位置被删） | 项目目录、下载目录 |

`categoryKind()` 是纯函数：显式 `kind` 优先，否则 `syncDir → mapped`、其余 `shortcut`。
**读取时不回写** —— 老数据零迁移风险，等用户真正编辑分类时再落盘。

## 存储盒的几个硬约束

1. **落点**：`<数据目录>/stash/<分类id>/`，跟数据目录一起搬走，换机器能带走。
2. **不覆盖**：同名文件依次退到 `name (2).ext`、`name (3).ext`…
3. **跨盘**：`rename` 失败会退化成「复制后删源」，目录递归复制；删不掉源目录会明确报错。
4. **不留半成品**：`stash_import` 先整批校验路径，缺一个就整批失败，不会搬一半。
5. **删除护栏**：`stash_delete` 先把目标规范化，再要求它必须在 `<数据目录>/stash` 之内，
   否则拒绝 —— 这个命令会被前端用数据文件里的路径调用，不能当通用 `rm` 使。
6. **分类 id 会做目录名**，所以只放行 `[A-Za-z0-9_-]`，挡住 `..\\` 这类穿越。

## 怎么用

1. 文件管理 → 新建分类 → 填名字
2. 弹出三选一：**快捷 / 存储 / 映射**
   - 存储：之后往这个分类的栅栏里拖文件，文件会被移进 stash，栅栏里出现指向副本的条目
   - 映射：紧接着选一个真实文件夹，内容和目录保持一致

## 验证

- `npm run verify`：`tsc` 覆盖 kind 与派生函数，`cargo test` 覆盖 Rust 侧。
- 手测：建一个存储盒 → 从桌面拖一个文件进它的栅栏 → 原位置的文件消失、
  `<数据目录>/stash/<分类id>/` 里出现副本 → 删条目时确认「连副本一起删」，
  副本消失；点取消则副本还在。

## 能力边界（三类盒子各自能做什么）

| 操作 | 快捷（shortcut） | 存储（storage） | 映射（mapped） |
| --- | --- | --- | --- |
| 拖图标进/出盒子 | ✅ | ✅ | ❌（内容是磁盘目录的镜像，拖出等于删文件） |
| 多选图标 → 新建盒子 | ✅ | ✅ | ❌ |
| 解散盒子（内容回到默认分类） | ✅ | ✅ | ❌ |
| 盒子内自由排序 | ✅ | ✅ | ❌（顺序由目录决定） |

**为什么映射盒子不开放这些操作**：它的内容不归云台管，归磁盘上那个真实目录。
「拖出去」「解散」在映射语义下没有对应动作 —— 删除盒子＝解除映射，文件仍在原处；
删除条目＝删文件，那是文件管理器的职责，不在卡片里做。
