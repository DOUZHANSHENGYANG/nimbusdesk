# 标签卡片仓（技能 / MCP / 提示词共用）

标签筛选从「一行药丸」换成**分组卡片**：每组一张卡，卡内多选，选中的进篮子；「管理」页整页是治理台 —— 左侧分组可增删改与排序，中间按分区分组维护每个标签的归属。

侧栏是**一整根栏**（`<aside>` 一张淡底 + 圆角），里面两块内容 —— 预设 / 标签 —— 叠在同一张底上，
各自**不画外框**：分区标题一行（10.5px 灰）、内容行（预设 h-7 / 12px，标签 chip h-6 / 11px），
区块之间只用 12px 间距和一条极淡的分隔线，不做卡片套卡片 ——
窄栏里嵌套盒子会把留白吃光、每一行都显得挤（Linear / Notion / GitHub 的侧栏都是这个路子：一行一个区）。
三页的侧栏统一 212px 宽、同一套行高与字阶，切换页面时左栏不跳。

## 为什么换

原来的 `TagFilter` 把标签、来源筛选、视图切换挤在同一层：标签一多就铺满两行，看不出标签属于哪个维度，也说不清「这些标签在筛什么」。

## 数据模型

标签本身仍是技能/MCP/提示词上的字符串数组，新增的只有一张「标签 → 组」的映射：

- `useTagGroups`（`src/ahub/stores/tag-groups.ts`，持久化键 `tag-groups`）；
- 纯逻辑在 `src/ahub/lib/tag-groups.ts`：`groupTags` / `assignTag` / `addGroup` / `removeGroup` / `renameGroup` / `pruneGroups`；
- 不迁移旧数据：没归组的标签显示在「未分组」卡里；删组只是把标签放回「未分组」，不会跟着消失。

## 交互

- 左栏「标签」右上角的**齿轮**打开治理台**弹框**（`TagManagerDialog`）：左侧分组（可排序 / 改名 / 删组）、中间按**可折叠分区**分组的标签表（勾选后批量归组、行内分组下拉、使用次数）。原来右栏那栏「当前命中 + 统计」已删：条数左栏和列表里都有，白占一列宽，删掉后表格整列更宽。
- 治理台**不再是页面级「列表 / 标签」页签**：整理标签是一次性动作，做完就回列表，为它把整页内容换掉不值得 —— 上下文没了，回来还要重新找刚才在看的那条。三个页面顶部那行页签也一并删掉。
- 点标签 = 加入/移出筛选；选满 2 个时出现「与 / 或」切换。
- **建组有三个入口**，都走同一套「建完立刻归位」的流程：
  1. 左栏底部「＋ 新建分组」—— 先建一个空组（组本身也是可排序的一等对象）；
  2. 批量栏「新建分组并移入」—— 选中若干标签后一步建组 + 归组（Linear 的用法：在使用处建组）；
  3. 行内分组下拉的最后一项「＋ 新建分组…」—— 这一条直接进新组（Gmail 的 Create new label）。
- **分组可排序**：左栏分组行悬停出现 ↑ / ↓ / 重命名 / 删除；顺序就是左栏与中间分区的显示顺序，直接落盘，没有保存按钮。用箭头而不是拖拽 —— 分组是个位数，拖拽省下的操作抵不上它带来的可达性问题。
- **分区可折叠**，未分组永远在最后一个分区，分区头显示条数；有搜索词时强制展开（搜出来的标签藏在折叠分区里等于没搜）。
- 同一标签只属于第一个命中的组；换组就是把旧组里的那一条摘掉。
- 标签数超过 8 个或正在搜索时，右上角出现「搜索标签」输入框。
- 标签本身**只读**：改标签要去条目自己（技能详情的标签字段、MCP / 提示词的标签框），这一页只维护「标签 → 组」的归属。

> 原「点标签收窄结果」提示文字与 ⌘K 检索面板（`TagCommand`、Ctrl+K 绑定）已按需求移除：
> 栏内不再有描述文字与快捷键入口。

## 顺带删掉

技能页顶部的「按来源筛选（harness）」整行：一页里只服务一种来源，占一整行没用。`harnessFilter` 状态与两处过滤条件一并删除。对应的 `HarnessFilterRail` 组件从此没有引用，已随这次改动删除。
