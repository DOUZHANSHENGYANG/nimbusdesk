# 全天待办、附件和本地存储

在计划管理中选择日期，点工具栏的桌面按钮曾可以显示这一天全部 Todo/subtodo。**该按钮已删除**
（纸片功能待整体拆除）：此前开着的纸片仍随启动恢复，但界面里暂时没有办法把新的一天放上桌面。
纸片支持创建、改名、完成、添加子任务；图钉控制置顶，关闭后不再随启动恢复。保留原来的收起、胶囊和窗口位置功能。

每个任务（包括子任务）都有“附件”入口。选择文件后复制到应用管理的目录，原文件保留；支持打开、在文件夹中显示和移除关联。移除关联不删除本地副本，以便撤销与归档。附件仍跟随稳定的任务 ID，移动日期不会改变所属任务。

数据目录可在设置中查看和更换：

```text
data/
  workbench.sqlite3
  modules/plans/tasks/<task-id>/attachments/<attachment-id>/<filename>
```

SQLite 的 `module_state` 按 module/feature/key 保存计划、归档、纸片、设置、收藏、订阅和知识库绑定等状态；保留原有 store 版本包裹。正文和大文件不放入数据库：Obsidian 的 Markdown、WikiLink 和 `assets/images/` 保持原位置，任务附件是普通文件。凭据继续使用已有系统凭据方案，旧 `ai-settings.json` 只保留给兼容迁移清理。

首次启动事务导入旧 JSON，原件保留，不会重复导入。数据库损坏或迁移失败时明确报错，不用旧 JSON 静默覆盖 SQLite。主窗与纸片之间按来源同步，事务内合并独立修改；同一字段冲突会显示保存错误并保留本地待写内容。关闭纸片、备份和更换目录前等待写入完成。更换目录使用 SQLite 快照并复制模块附件，目标冲突会中止，源目录保留。

备份格式 2 包含 11 个模块状态和被活跃/归档任务引用的附件本体，仍可读取格式 1。恢复先校验并写附件，再合并任务状态；不覆盖本机数据目录、知识库路径或系统凭据。附件每次添加一个文件（单文件最多 64 MiB），备份附件原始数据合计最多 128 MiB；分类目录备份仍只包含目录结构。

验证命令：`npm run verify`、`npm run build`。`check:plans` 覆盖附件并发、完整备份、失败重试及跨窗口持久化；Rust 测试覆盖真实 SQLite 事务、迁移、快照、文件二进制和 Windows junction。浏览器夹具和原生 UIAutomation 均使用独立临时数据。
