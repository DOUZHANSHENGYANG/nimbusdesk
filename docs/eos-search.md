# 奇妙搜索源（EOS）作为搜索后端

## 它是什么

社区维护的一份**搜索规则表**（[OrO-c/EveOneSearch](https://github.com/OrO-c/EveOneSearch)）。
每条规则只是一个 URL 模板，把 `{keyword}` 换成关键词就是那个站点的搜索页：

```json
{ "title": "皮卡搜索", "group": "网盘", "url": "https://www.pikasoo.top/search/?pan=all&q={keyword}" }
```

所以它**不是** API 聚合。我们要做的是：打开搜索页 → 从 HTML 里抽出结果链接。
这决定了它的性格：慢（单条 1–7 秒）、产出不均（实测 215 条里 37 条能抽出 ≥2 条结果）、
会随站点改版失效。

## 怎么用

设置 → 联网搜索 → 搜索后端选「奇妙搜索源」。之后资讯页的 AI 搜索走它检索。

一次搜索的实际行为：

1. `rankRules` 按健康度排序 —— 上次有产出的排前面，冷却中的直接跳过；
2. 6 个并发 worker 按顺序取规则，凑够 8 条结果**且**来自 ≥3 个不同站点就提前收工；
3. 9 秒总预算到点就返回已有结果（不会让用户干等）；
4. 每条规则的成败都记进健康度表。

## 失败自动失效

这是它能长期不维护的关键，实现在 `src/search/eos/health.ts`：

| 情况 | 处理 |
|---|---|
| 请求抛错 / 非 2xx | `recordFail`：连续失败 +1 |
| 页面打开但抽不到结果 | 同样 `recordFail` —— 改版成 JS 渲染的站点等于已经没用了 |
| 连续失败达到 2 次 | 冷却 12 小时，期间不参与搜索 |
| 冷却结束 | 给一次机会（半开），成功就清零 |
| 跨天 | 连续失败次数减半，一次断网不会永久拉黑 |

设置页会显示「当前 N/M 条可用」，出现冷却时给出「重置失效记录」按钮。

## 抽取规则

`src/search/eos/extract.ts`，纯字符串扫描（不引 HTML 解析器，也不依赖 DOM，所以能在 node 里单测）：

- **打分制**而不是硬过滤：锚文本含关键词 +3、URL 像详情页 +2、跨站 +1、文本够长 +1；
- **关键词与 URL 都不含它的链接直接丢弃** —— 那是站内推荐位；
- ASCII 关键词按词边界匹配：搜 `react` 不会命中 `Reactor`（实测 7723 一个站能靠这个刷满整屏）；
- 丢掉导航文字、备案/法务站、站内搜索框、安装包直链（`.apk`/`.exe`…）；
- 页面里直接出现的网盘/磁力/ed2k 链接额外提为高优先级结果，标题取锚点里的 `<h1>`–`<h4>`；
- 结果按来源轮转，每个站最多 2 条（填不满才放宽到 4）—— 否则 Naver 一条规则产出的 93 条会占满整屏。

## 内置规则快照

`src/search/eos/rules.json`，207 条，24 个分组，34 KB。由上游订阅文件转换而来：

- 丢弃 `⚠️使用者必看`（那是免责声明占位）；
- **丢弃所有 cookie** —— 上游有规则带明文 `csrftoken`，内置进应用等于替第三方保管凭据；
- 保留 `ua` / `referer`；
- 每条带 `yield` 字段记录首次排序用的实测命中数。

`站长工具` 分组（ICP 备案、拦截检测）不参与通用搜索 —— 它们只在输入域名时才成立，
搜 `react` 会给出「react 的 ICP 备案信息」。规则仍留在快照里。

上游更新后重新生成：解析订阅文件（去掉 `<JSON>` / `</JSON>` 包裹）→ 按上述规则转换 → 覆盖 `rules.json`。
`eos.test.mjs` 会校验每条规则都带占位符、无 cookie、id 唯一。

## 验证

```powershell
npm run check:feeds          # 13 条单测：URL 模板、抽取、噪音过滤、健康度冷却与衰减
```

真机验证：设置里切到「奇妙搜索源」，资讯 → AI 搜索，搜一个中英混合的词（如 `react`、`三体`），
确认结果来自多个不同站点且标题可读；再搜一个必然无结果的词，确认不会卡住超过 9 秒。

## 已知边界

- **不保证质量**。它是社区规则的集合，不是搜索引擎。搜技术问题时 Bing/Tavily 明显更好。
- **13 秒左右的耗时是常态**（预算 9 秒 + 单条超时）。不适合做成输入即搜。
- 规则会随站点改版持续失效，靠健康度自动降权，不会自动修复。
- 没有 UI 让用户增删规则，只有内置快照。
