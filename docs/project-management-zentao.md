# 禅道连接与本地任务补绑定（第二阶段）

后续已增加键盘优化与普通字段受控回写，见 [交互与回写说明](project-management-writeback.md)。以下保留第二阶段的实现与验证记录。

入口：**项目管理 → 禅道连接**。现在即可保存多份连接草稿，地址和账号可留空。没有完整配置时不发送登录或任务请求。

## 接入步骤

1. 新建连接，填写名称、禅道安装地址和账号。地址支持子目录，例如 `https://zentao.example.com/zentao/`；不要填带凭据或查询参数的地址。
2. API 默认自动识别，也可手动指定 v1 / v2。输入密码或 Token，点击“验证并保存凭据”。同时填写时优先使用密码；两项都留空时验证本机已保存的 Token。
3. 点击“立即同步”。默认读取分配给自己／自己参与的多人任务，可用执行 ID 缩小范围。同步在后台运行，关闭连接面板也会继续；上次成功时间、数量及失败原因保留在面板中。
4. 自动同步默认关闭。开启后仅在应用运行或驻留托盘时按间隔执行，网络失败按间隔重试；认证／权限失败暂停，需重新验证连接。恢复备份的连接一律关闭自动同步并要求验证。

禅道“执行”与本地个人迭代是不同实体。同步缓存保留执行信息、日期与来源，不擅自创建个人项目或改变个人排期。新同步工作项先处于“未排期”；列表有被当前筛选隐藏时提供直接入口。

## 先做计划，后补禅道任务

在本地工作项详情选择“关联禅道”，搜索已经同步的任务。不同连接下相同的任务编号互不混淆，不按标题自动匹配。

如果来源已经导入成另一条工作项，先展示两条工作项及关联计划／历史数量。标题、备注、截止日期和状态可逐项选择保留本地或采用来源值。导入工作项另外做过的本地修改会单独比较展示，完整原值保存在只读合并记录中。

确认后保留当前本地工作项的 ID、项目分类和当前迭代；原导入工作项标记为已合并，保留合并前快照、原备注和迭代记录。两边活跃与归档计划的显式关联统一指向当前工作项，子计划继续继承父关联，附件和磁盘文件不移动。缺少的迭代历史复制为已结束记录，原记录仍保留。整个项目／活跃计划／归档计划通过一个 SQLite3 事务提交。

仅当提交结果没有额外合并其他窗口修改、且之后三个模块仍与提交时一致时提供安全撤销；有后续改动时拒绝旧快照覆盖。

## 同步与数据保护

- 缓存和来源关联以“连接 ID＋任务 ID”唯一标识，重复同步不会重复导入。
- 每个来源保存同步基线。未在本地修改的字段可跟随云端更新；本地修改保留，双方同时修改的字段标记差异供查看。第二阶段不回写公司的任务。
- 任务改派、关闭或离开当前筛选后，已知任务尝试详情补读；404／无权限保留旧缓存，不推断删除。分页、响应或网络失败不应用部分结果。
- v2 的“我的工作”接口不返回首次同步前已关闭／取消的历史任务；已同步过的任务仍通过详情补读跟进关闭状态。本阶段不是全公司的历史任务镜像。
- 禅道列表对部分子任务及“需求变更”状态有展示加工，对这些行详情补读以取得实际名称、父任务和状态。
- 已有缓存任务后，连接地址和账号锁定；换服务器或账号请新建连接，避免不同来源串号。请求期间身份／范围变化会拒绝旧结果。
- 密码和 Token 使用独立的 Windows 凭据管理器命名空间；不写 SQLite、JSON、备份或日志。删除可删除的连接草稿前先清除其本机凭据。已有来源任务的连接保留，支持停止自动同步与清除凭据。
- 接口只发送认证 POST 和读取 GET，不发送任务更新。禁用 HTTP 重定向；原始错误响应不进入界面或日志。
- 有分页、响应大小、任务数量和超时上限。一次最多补读 1,000 个已知任务，最多 200 页；单响应 8 MiB，单请求最长 15 秒，单次操作最长 120 秒。超过上限整体失败并保留缓存，可缩小执行范围。
- SQLite schema 2→3 的迁移保留原模块 JSON，新增来源缓存与唯一关联索引。备份包含公共连接配置、缓存、基线与合并记录；恢复项目／计划使用同一原子事务。

## 验证边界

实现依据公开禅道 22.6 源码，固定审阅版本 `d5bfff8c91cea48018275381e0a127ed6fa5c79f`：`config/apiv1.php`、`config/apiv2.php`、路由认证、我的工作与任务详情实现。客户端为本项目独立实现，未引入外部项目依赖。

验证入口：`npm run check:projects`、`npm run check:plans`、`npm run verify`，以及 `node scripts/check-zentao-browser.mjs`（先启动项目 Vite，默认端口 17800）。原生客户端使用本地 TCP 服务覆盖实际 HTTP、认证头、分页及错误行为；浏览器使用模拟原生边界验证真实组件。截图与日志写入忽略的 `Temp/`。

2026-10-18 本机验证结果：全量 `npm run verify` 通过（335 项前端测试、252 项 Rust 测试，1 项原有忽略测试）；项目专项 36/36、计划／备份／存储专项 68/68、浏览器操作 10/10；前端生产构建和 Tauri 原生构建通过。Windows 凭据管理器使用独立临时测试项完成真实保存、读取、账号／地址隔离与删除，并确认清除。原生应用已重新启动，UI Automation 打开“禅道连接”面板确认入口可用，未创建演示公司配置。实际便携数据库迁移到 schema 3，`quick_check` 通过，项目及两份计划模块迁移前后 JSON 哈希一致。

本轮使用 writing-plans、TDD、verification-before-completion 和 code-simplifier 流程，独立复核修复了并发提交后撤销可能覆盖另一窗口编辑的问题；GitHub MCP 核对公开版本，接口细节以固定源码审阅为准。未安装依赖。前序成果已提交为 `52a629c`（桌面交互）和 `40ff59e`（本地项目管理），第二阶段改动保留工作区供审阅，未推送。

尚无公司地址／账号，因此没有验证公司网络、部署路由、权限和登录策略。提供连接信息后需在本机完成真实连通性及任务数量校验。第三阶段再实现回写与可视化冲突处理。
