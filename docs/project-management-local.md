## 使用方式

- 在侧栏进入“项目管理”。先新建业务范围或项目，也可直接新建不属于项目的小任务。
- 迭代支持两周、三周预设和自定义起止日期。默认按周一至第二/三周周五填写，日期始终可修改。项目范围与迭代筛选独立。
- “看板”与“工作项”共用同一份筛选（迭代/状态/搜索）和同一批卡片：四列按状态排列，拖动卡片即改状态；卡片左侧圆点按钮快速完成/恢复。键盘路径是回车开详情、在详情里改状态。看板在“全部项目/区域”范围也可用，项目资料页仍只在选中项目时出现。
- “总览”是这一页的落地视图，一屏摊开现状：状态分布与完成率（分母剔除已取消）、当前迭代的进度条与剩余天数、需要关注（逾期/今天/未来 7 天）、项目进度（点一行即把范围收到那个项目或业务范围）、最近改动。它只看范围与迭代，不吃状态筛选与搜索——统计状态分布时再按状态筛会自相矛盾；点其中任一条就在这一屏右侧开详情，不跳去列表。
- 从任务详情派生每日计划，或在现有计划行选择“关联项目任务”。子计划默认继承父计划，可覆盖为另一任务，也可明确保持游离。
- 结转只调整本地排期，保留任务 ID、原迭代快照和历史计划。任务完成与每日计划勾选相互独立。
- 项目可不绑定目录、绑定已有目录，或创建工作台托管目录。资料支持目录导航、新建、复制导入、明确确认后移动、重命名、移动到其他子目录、回收站及系统打开。
- MD/TXT 可预览编辑，图片可预览；外部程序修改文件后，冲突展示磁盘版与草稿，支持保留草稿/另存。保存期间继续输入的文字保留，不被较早的请求回写清掉。
- 截止提醒默认 09:00、16:50，优先任务截止日期，无则取任务明确选定迭代的结束日。支持全局、项目与任务覆盖，时间、时区、工作日和提前天数可修改。
- 应用运行或驻留托盘时调度；错过的当日时段合并补发，发送成功才记送达记录。通知权限不足时提示授权，不标成发送成功。

## 存储与恢复

沿用 `workbench.sqlite3`，schema 1→2 增量迁移。新增业务、项目、迭代、工作项、成员关系和计划关联六张关系表；各模块的原始状态保留兼容包裹。关联与计划元数据同一事务写入，撤销/重做无需拼接第二份独立关系状态。

活跃/归档计划共同变更采用双库快照及原生 SQLite 原子事务，包括归档、恢复、撤销、重做。第二份写入、关联校验或并发合并失败，全部回滚；并发写入期间排队的转换不会拆成两次提交或滞留在失效的防抖计时器后。

项目备份保存分类、项目、任务、迭代历史、关联和提醒记录；恢复保留本机数据，按稳定 ID 与修改时间合并，悬空关联先拒绝。外来项目目录绑定不会直接覆盖本机绑定。勾选覆盖设置时才恢复全局提醒偏好。

JSON 备份不打包项目目录中的正文文件；该边界与原分类资料备份一致，重要外部目录请继续使用既有文件备份。工作台托管资料使用 `modules/projects/materials/<id>` 相对绑定，完整数据目录搬迁会复制资料并保留空目录，原始文件保留。
