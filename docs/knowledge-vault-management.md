# 知识库：管理面

「知识库」页（`/ai/knowledge`）分两个面：**工作区**（原「管理」）与**归档区**（原「笔记」）。

- **工作区**（默认）—— 收件箱 / 审核区 / 待归档区 / 经验区 / 冷知识区。只做判断与搬运，不编辑正文。
- **归档区** —— 只展示正式区（01~04）的笔记：浏览、阅读、编辑、移动到别处、改名。人类区与 AI 区的内容不在这一面出现。

## 管理面只有三件事

管理面是**一张表**：上方切换 收件箱 / 审核区 / 待归档区 / 经验区 / 冷知识区；右侧是来源筛选下拉（全部 / AI / Human），只在有来源的三个面出现。收件箱 = 人类区 Inbox，审核区 = AI 区 Inbox，两者不重复展示。待审表的每行点「审核」打开审核弹窗：左边输入（来源与路径）、右边输出（正文预览），下面定「归档类型 → AI 建议路径 → 最终归档地址（可改）」，再点「通过并送审」。

| 面 | 你要做的 | 系统做什么 |
| --- | --- | --- |
| 待审 | 看一眼内容、选归档类型，点「通过」或「退回」 | 通过 = 写 `type` / `archive_to` 并移到同区 `已审核`；退回 = 移到同区 `Trash`（不删文件） |
| 待归档 | 「确认归档」一次搬完 | `archive.py plan/run` 搬运、改名、回写 `archived_to`；`archive_to` 优先于 `type` 决定的目录 |
| 经验 | 不用动手，等案例攒够 | 从案例算状态、写回 `wiki_state` |

**经验的定义**：同一主题 3 个以上真实案例、且至少被用过一次，才算一条经验；不足 3 例只是「假设」。**冷知识区**列的是长期没被引用、被 `promote.py cold` 移到 `wiki/cold/` 的案例（只移动不删除）。

「待审」列表顶上会有一条 **「N 处可以在入库前自动修好」→ 一键修好**：只修两类机械问题——状态写成词表外的值（映射到草稿/已发布）、文件带/缺隐藏字符（`kb.py fixbom`）。**只看 Inbox 里的文件**，正式区不动。

再右边是**只提醒、不处理**的徽标：「草稿超期 N」「文件头损坏 N」——点一下才展开那句话，鼠标悬停能看到前 5 个路径。这类问题要回 Obsidian 改，工作台只负责让你看见。

类型和归属不在「要修」里出现：类型在审核时定（AI 按目录给建议，你可以改），归属是二分——没有 `human` 就是 AI 写的，不单独报。

## 笔记面的结构

- **三个区**：`00-Human工作区` / `00-Agent工作区` / `01~04`。分区里的分类就是真实目录，目录改名界面跟着变。
- **扫描范围以 `99-系统/config.yaml` 的 `areas` 为准**：没声明的目录（缓存、临时目录、别的库）不进列表。
- **工作区**：收件箱 = `00-Human工作区/Inbox`（人放的材料，右上「上传文件到收件箱」，可多选、同名不覆盖）；审核区 = `00-Agent工作区/Inbox`（AI 写的稿，等人审）。两边不重复展示。
- 顶部按钮 **打开收集弹框**（原「收集知识」）固定把材料存进 `00-Agent工作区/Inbox/工作台/`：一张卡片放标题、正文、图片附件；图片是「左缩略图 + 右文件名」的列表，双击文件名改名；底部只有一个「保存到 AI 收件箱」。窗口标题下面显示库名，没有「保存到收件箱」说明行、没有快捷键提示、没有草稿状态行。
- **归档区**只列正式区（`01~04`）；右栏可以「移动到…」「重命名」，移动与改名都会重写库内 wikilink（`[[路径]]`、`[[路径|标注]]`、`[[路径#小节]]`）。

## 数据通路

```
React（vault-manager.tsx / page.tsx）
  → invoke("knowledge_vault_tool", …)     体检 / 分诊 / 闭环（读库内 py 工具的 --json）
  → invoke("knowledge_scan" / "knowledge_move" / "knowledge_rename" / "knowledge_import" …)
  → 直接读写库内文件（同名不覆盖、拒绝越界路径）
```

规则只存在库内一份：目录与词表在 `99-系统/config.yaml`，归档去向在 `archive.dest_map`，脚本在 `99-系统/manage/tools`。

## 设置页

知识库设置里只留三块：

- **Obsidian 知识库**：绑定 / 换绑（不移动文件）
- **库配置**：只给两个按钮（打开 `99-系统/config.yaml`、打开模板目录）；路径由库自动探查，界面不再罗列
- **快捷收集**：快捷键与置顶面板

AI 自动整理仍然有效：整理范围只剩「两个区的 Inbox」（不再有"全部管理目录"），写作模板/整理偏好/定时/是否发送图片都照旧；产物落在 AI 区 Inbox，等人审。

原先「知识分类文件夹」那三个绑定路径已经删掉——分类来自库结构，不来自应用配置；归档落点由 `archive.py` 读 `config.yaml` 决定。

## 怎么验证

```powershell
npm run tauri dev        # 桌面窗口，管理面要真的 IPC 才能出数据
npm run check:knowledge
cargo test --manifest-path src-tauri/Cargo.toml --lib knowledge
```

**不用起桌面壳也能看界面**：`src/features/knowledge/fixtures/manager.html`（真组件 + mock IPC），`npm run dev` 之后打开

```
…/manager.html                  # 管理面 · 待审
…/manager.html?mcat=1           # 待归档
…/manager.html?mcat=2           # 经验
…/manager.html?view=notes       # 笔记面 · 正式区
…/manager.html?view=notes&zone=0 / &zone=1   # 人类区 / AI 区
…/manager.html?state=empty      # 空
…/manager.html?state=error      # 库内脚本跑不起来
…/manager.html?state=slow       # 加载中
```

## 已知限制

- 「一键修好」对状态是逐篇按指纹写入（外部改过的那篇会跳过），隐藏字符交给 `kb.py fixbom`。
- 上传支持系统多选，也支持把文件拖进窗口（只在人类区 / AI 区生效；正式区拖入不处理）。
- 待审只收两个 `Inbox` 的直接子目录，不含 `_raw/` 原文层和 `工作台/` 采集暂存。
- 「AI 自动整理」的产物现在落在 `00-Agent工作区/Inbox/`，走完「待审 → 已审核 → archive.py」才算归档；内容类型只决定模板与 `type`，不再直接写进正式区。
