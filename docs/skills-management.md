# 技能与 MCP 管理

技能（Skills）与 MCP 服务都收在同一页「工具管理」下的两个标签里，共用一套
「从本机收集 → 应用到本机」的搬运逻辑。

## 收集面板

打开面板就会**扫描本机所有已知工具**（Claude Code / Codex CLI / Pi Agent /
OpenCode / WorkBuddy / CodeBuddy / DeepSeek），并把扫到的条目**默认全选**。

> 之前只有 MCP 默认全选、skills 留空勾选，于是「一键收集全部」看着像没激活。
> 现在两边同一套语义：能收的先勾上，用户只做减法。

## 导入向导里的四件事

| 能力 | 说明 |
|---|---|
| 程序修复 | 目录名、`name` 字段、`SKILL.md` 大小写、描述缺失，先由程序修 |
| AI 修复 | 修不了的交给 AI 补描述（provider 不可用就保留原描述，记一条跳过） |
| **详情** | 每条候选右侧点「详情」→ 只读弹窗：**SKILL.md 正文 + 目录树**（复用 `SkillFileBrowser`），不写盘、不影响勾选 |
| 冲突处理 | 同名技能默认覆盖，可逐条取消（取消后同名冲突记为失败） |

## 导入后打标签

新建空白技能时标签在表单里选；从 ZIP / 文件夹 / Git 仓库 / 市场导入的条目，
导入成功后会自动弹出批量打标签弹窗，作用范围就是**刚导入的这一批**，不用再回列表
重新勾选。也可以直接关掉，之后再用批量工具条补。

标签来源与「标签治理」一致：`TagPicker` 按分组列出已有标签，也能当场新建。

## 批量操作

技能页多选模式（工具栏右侧「批量选择」）：

| 动作 | 说明 |
|---|---|
| 全选 / 取消全选 | 只作用于当前过滤结果，搜索/标签筛选下不会误选被筛掉的 |
| 接入工具 | 选工具 → 批量复制到工具技能目录，或从工具目录移出副本；按工具报成功/失败 |
| 批量打标签 | 追加 / 移除 / 清空，新建与编辑共用一套标签选择器 |
| 生成摘要 | 调 AI 逐条生成描述 |
| 流水线 | 审查 → 摘要 → 打包，三步一条链（见下） |
| 打包导出 | 打包成 `.zip` / `.skillpack` |
| **批量启用 / 停用** | 逐个调 `setSkillStatus`；结束报「成功 N / 失败 M」 |
| 批量删除 | 二次确认后删除 |

逐个调而不是新开批量命令：状态要写回每个技能自己的元信息，失败也只该影响那一个。

## 发版流水线

批量工具条里选好技能 → 「流水线」：**审查（体检）→ AI 摘要 → 打包导出** 依次执行，
每步有自己的状态与「重跑」，某步失败不用从头再来。

| 步骤 | 调用的命令 | 说明 |
|---|---|---|
| 审查（体检） | `onboard_skills_batch(targets, false, true)` | 补 `SKILL.toml` + 规则体检，返回建议级别；未通过的数量写在结果里 |
| AI 摘要 | `skill_generate_summary_batch` | 生成一句话描述，写回 `.hub.json` |
| 打包导出 | `pack_skills_batch(targets, outDir)` | 导出 zip 与 `index.json`；没选目录时这步显示「已跳过」 |

截图：`docs/screenshots/skill-pipeline.png`。

## 工具维度（harness）

技能卡片底部会列出这份技能**已经接进了哪些工具**（Claude Code / Codex / Gemini CLI…），
左栏标签仓下面是「工具」区块：每行是该工具下的技能条数，点一下就把列表收窄；
「未接入工具」把所有工具目录里都没有副本的技能挑出来 —— 这些是最适合清理的一批。
列表右上角的视图切换多了一档「按工具」：按接入关系分组（一份技能接了多个工具就会
出现在多个组里），最后是「未接入工具」组。

批量接入：多选技能 →「接入工具」→ 选工具 → 执行。对话框顶部可切 **接入 / 移出**，
每行写明「将新增 n 项 / 将移除 n 项」，跑完按工具报 `✓ 成功 / ✕ 失败 / — 跳过`。
移出只删该工具技能目录里的副本（校验目标目录确实是含 `SKILL.md` 的技能目录，且名字
不能带路径分隔符），中枢库里的原技能不受影响。

**关于「上次使用」**：各 harness 都不暴露运行时的技能调用记录，所以这里用工具目录里
`SKILL.md` 的修改时间作为「上次同步到该工具」的时间；详情页头部会列出每个工具与日期，
卡片徽标 hover 也能看到。从未出现在任何工具目录里的技能显示「未接入任何工具」。

空态：0 个技能时给出 **ZIP / 文件夹 / Git 仓库** 三张入口卡（直接打开添加对话框的对应
入口），另有「扫描本机」。

截图：`docs/screenshots/tag-shelf.png`（徽标 + 工具区块）、
`docs/screenshots/harness-groups.png`（按工具分组）、
`docs/screenshots/harness-filter.png`（按「未接入工具」收窄）、
`docs/screenshots/harness-batch.png`、`harness-batch-remove.png`、`tag-empty.png`。

## 本机工具里的技能（工具箱 → 本机工具）

技能页只服务**自己的技能池**：卡片不再显示「来自 OpenCode / Claude Code」这类来源徽标，
来源归因不再占卡片位置。要看**各工具目录里到底有什么**，去「工具 → 本机工具」页的
「本机技能」区：

- 按工具分组列出每个技能副本，标出「池内 / 仅在此工具」；
- 「覆盖更新」把池内同名技能重新写入该工具；「导入到池子」把只在工具里的技能收进中枢；
- 「打开目录」定位到该技能文件夹；「移出」只删这个工具目录里的副本，删前确认。

截图：`docs/screenshots/harness-skills.png`。

## MCP 的工具维度（与技能同一套）

MCP 页用的是同一套抽象：左栏标签仓下面同样有「工具」区块（按 `targets` 统计，
带「未接入工具」），卡片上显示已写入哪些工具、没写过的显式标「未接入任何工具」。

批量选择 →「接入工具」打开与技能共用的对话框：切「接入 / 移出」两个方向，
每行写将新增/移除多少项，执行后按工具报成功、失败、跳过。写入成功后同步
`targets` 元数据（`save_mcp`），所以卡片徽标、工具筛选和中枢记录始终一致。

单个工具内的「更新配置 / 解绑」仍在工具配置对话框里（打开某工具后逐条操作）；
批量跨工具用上面这个入口。

截图：`docs/screenshots/mcp-rail.png`、`mcp-harness-batch.png`。

## 批量检查上游更新

页头「检查更新」：勾了技能就只查勾选的，没勾就查全部，逐个跑 `check_upstream`
（每个技能一次 `git ls-remote <remote> HEAD`），结果显示在「上游检查结果」弹窗里，
按 **有新版本 → 检查失败 → 未跟踪 → 已是最新** 排序，点任意一行直接打开那个技能。

跟踪开关与上游地址在技能详情 →「来源与更新」里配置（`[source.upstream].watch = true` +
`mode = "git-scan"` + `remote`）。没开跟踪的技能会显示「未跟踪上游」，不会被当成检查失败。

截图：`docs/screenshots/upstream-check.png`。

## 版本时间轴与差异

技能详情右栏、提示词编辑器右栏的「版本时间轴」由两个开源组件拼起来，不再自己写：

| 部分 | 组件 | 为什么 |
|---|---|---|
| 竖线 / 节点 / 卡片 / 展开动画 | `react-vertical-timeline-component@4` | 竖轴这套几何与动画它已经调好，我们只覆盖颜色与间距 |
| 逐行与词级差异 | `react-diff-viewer-continued@4.4` | 行号、词级高亮、折叠上下文都有，颜色通过 `var(--…)` 传进去，跟随主题 |

配色不写死：`src/ahub/styles/version-timeline.css` 里所有颜色都取自 `tokens.css` 的
`--surface` / `--border` / `--success` / `--danger` 等，深浅主题自动跟随。

用法：技能详情 → 右栏时间轴 → 点某一版 → 「当前 / 上一版」切换对比基准 → 看差异 → 「恢复」。

## 来源机制（已关掉）

导入向导里的「来源确认」步骤**默认关闭**（`SOURCE_STEP_ENABLED = false`）：
步骤条只显示 探查 → 无法修复 → AI 修复 → 执行，进入向导时也不再预置来源，
导入执行拿到的是空表 —— 相当于不再给技能写来源归因。

保留代码与开关是为了能一键恢复；已存在条目上的 `source` 字段与标签**一律不动**
（删字段要写数据迁移，属于另一件事）。

## 验证

- `npm run check:i18n`：ahub 那份词表（`src/ahub/i18n/index.ts`）zh/en 必须对齐，
  缺 key 会直接把 `skillImport.xxx` 画到界面上。
- 手测：打开收集面板 → 条目默认已勾选；点某条「详情」能看到 SKILL.md 与目录树；
  技能页进多选 → 选两条 → 批量停用 → 状态变灰且提示「成功 2 / 失败 0」。
- 手测工具维度：卡片底部能看到「已接入 Claude Code …」；点左栏「未接入工具」后只剩
  一个工具都没接的技能；多选两条 →「接入工具」→ 勾一个工具 → 执行 → 每个工具行显示
  ✓ 成功数，详情页头部出现该工具与最近同步日期。
