# 技能与 MCP 管理

技能（Skills）与 MCP 服务各自在「技能」「MCP」页管理，工具本身在「Harness 工具」页；
两边共用一套「从本机收集 → 应用到本机」的搬运逻辑。

## 收集面板

打开面板就会**扫描本机所有已知工具**（Claude Code / Codex CLI / Pi Agent /
OpenCode / WorkBuddy / CodeBuddy / DeepSeek），并把扫到的条目**默认全选**。

> 之前只有 MCP 默认全选、skills 留空勾选，于是「一键收集全部」看着像没激活。
> 现在两边同一套语义：能收的先勾上，用户只做减法。

## 导入向导里的四件事

| 能力 | 说明 |
|---|---|
| 程序修复 | 目录名、`name` 字段、`SKILL.md` 大小写、描述缺失，先由程序修 |
| AI 修复 | 修不了的交给 AI 补描述（provider 不可用就保留原描述，记一条跳过） |
| **详情** | 每条候选右侧点「详情」→ 只读弹窗：**SKILL.md 正文 + 目录树**（复用 `SkillFileBrowser`），不写盘、不影响勾选 |
| 冲突处理 | 同名技能默认覆盖，可逐条取消（取消后同名冲突记为失败） |

## 导入后打标签

新建空白技能时标签在表单里选；从 ZIP / 文件夹 / Git 仓库 / 市场导入的条目，
导入成功后会自动弹出批量打标签弹窗，作用范围就是**刚导入的这一批**，不用再回列表
重新勾选。也可以直接关掉，之后再用批量工具条补。

标签来源与「标签治理」一致：`TagPicker` 按分组列出已有标签，也能当场新建。

## 批量操作

技能页多选模式（工具栏右侧「批量选择」），按钮按使用频率分两行：

第一行（常用工具）：

| 动作 | 说明 |
|---|---|
| 全选 / 取消全选 | 只作用于当前过滤结果，随选中状态自动切换文案 |
| 打包导出 | 打包成 `.zip` / `.skillpack` |
| 保存为预设 | 把当前勾选写成一个命名集合；选中预设时多一个「保存修改到预设」 |
| 批量删除 | 二次确认；有工具副本时可勾选「同时从工具移出」，默认勾选 |

第二行（批量功能）：

| 动作 | 说明 |
|---|---|
| 纳入技能管理 | 生成 SKILL.toml（已纳入自动跳过）+ 安全审查 |
| 智能摘要 | 调 AI 逐条生成描述 |
| 智能标签 | 追加 / 移除 / 清空，新建与编辑共用一套标签选择器 |

已移除：发版流水线、批量接入工具（改走页头「批量配置」按工具管理）、
批量启用 / 停用（状态在技能详情里改）。

删除确认截图：`docs/screenshots/skill-delete-harness.png`（默认勾选「同时从工具移出」，
并列出 Claude Code 等工具名）。批量两行按钮：`docs/screenshots/skills-batch-rows.png`。

## 发版流水线（已移除入口）

流水线入口已从批量工具条移除（用的人少，且三个步骤都能单独跑）；组件
`SkillPipelineDialog` 保留，需要时可恢复。原先的用法：

| 步骤 | 调用的命令 | 说明 |
|---|---|---|
| 审查（体检） | `onboard_skills_batch(targets, false, true)` | 补 `SKILL.toml` + 规则体检，返回建议级别；未通过的数量写在结果里 |
| AI 摘要 | `skill_generate_summary_batch` | 生成一句话描述，写回 `.hub.json` |
| 打包导出 | `pack_skills_batch(targets, outDir)` | 导出 zip 与 `index.json`；没选目录时这步显示「已跳过」 |

截图：`docs/screenshots/skill-pipeline.png`。

## 工具维度（harness）

技能卡片底部会列出这份技能**已经接进了哪些工具**（Claude Code / Codex / Gemini CLI…），
左栏标签仓下面是「工具」区块：每行是该工具下的技能条数，点一下就把列表收窄；
「未接入工具」把所有工具目录里都没有副本的技能挑出来 —— 这些是最适合清理的一批。

批量接入已从批量模式里移走：改用页头「批量配置」（见下文「按工具管理」），
按工具集中接入 / 解绑，与 MCP 页同一套交互。

技能列表只有**网格视图**（一行四张，与 MCP 页一致），不再提供「分组」视图。
卡片不展示描述：第一行小字是状态（版本号 / 审核状态 / 生命周期 —— 中文界面显示
草稿、已弃用、已归档），第二行是标签；更新时间格式化为「2026年9月1日 13点21分」，
打开文件夹与删除按钮悬停卡片时出现。卡片截图：`docs/screenshots/skills-grid-cards.png`。
移出只删该工具技能目录里的副本（校验目标目录确实是含 `SKILL.md` 的技能目录，且名字
不能带路径分隔符），中枢库里的原技能不受影响。

**关于「上次使用」**：各 harness 都不暴露运行时的技能调用记录，所以这里用工具目录里
`SKILL.md` 的修改时间作为「上次同步到该工具」的时间；详情页头部会列出每个工具与日期，
卡片徽标 hover 也能看到。从未出现在任何工具目录里的技能显示「未接入任何工具」。

空态：0 个技能时给出 **ZIP / 文件夹 / Git 仓库** 三张入口卡（直接打开添加对话框的对应
入口），另有「扫描本机」。

截图：`docs/screenshots/tag-shelf.png`（徽标 + 工具区块）、
`docs/screenshots/harness-groups.png`（按工具分组）、
`docs/screenshots/harness-filter.png`（按「未接入工具」收窄）、

## Harness 工具总览（技能 + MCP）

「Harness 工具」最上面是一张总览表：每个 harness 一行，同时给出**技能副本数**、
**MCP 数**、**待更新技能数**（中枢里的版本比工具目录新）以及配置是否找到。
它回答的是「本机这些工具里到底有什么」，具体操作仍在下面的「本机技能」和 MCP 页里。

截图：`docs/screenshots/harness-overview.png`。

## Harness 工具里的技能（Harness 工具页）

技能页只服务**自己的技能池**：卡片不再显示「来自 OpenCode / Claude Code」这类来源徽标，
来源归因不再占卡片位置。要看**各工具目录里到底有什么**，去「Harness 工具」页的
「本机技能」区：

- 按工具分组列出每个技能副本，标出「池内 / 仅在此工具」；
- 「覆盖更新」把池内同名技能重新写入该工具；「导入到池子」把只在工具里的技能收进中枢；
- 「打开目录」定位到该技能文件夹；「移出」只删这个工具目录里的副本，删前确认。

截图：`docs/screenshots/harness-skills.png`。

## MCP 的工具维度（与技能同一套）

MCP 页用的是同一套抽象：左栏标签仓下面同样有「工具」区块（按 `targets` 统计，
带「未接入工具」），卡片上显示已写入哪些工具、没写过的显式标「未接入任何工具」。

批量选择 →「接入工具」打开与技能共用的对话框：切「接入 / 移出」两个方向，
每行写将新增/移除多少项，执行后按工具报成功、失败、跳过。写入成功后同步
`targets` 元数据（`save_mcp`），所以卡片徽标、工具筛选和中枢记录始终一致。

单个工具内的「更新配置 / 解绑」仍在工具配置对话框里（打开某工具后逐条操作）；
批量跨工具用上面这个入口。

0 个 MCP 时不再是空白：空态直接给「从 JSON 粘贴」与「从工具导入」两个入口，
顶部「扫描本机」「新建 MCP」仍然可用。

截图：`docs/screenshots/mcp-rail.png`、`mcp-empty.png`、`mcp-harness-batch.png`。

## 批量检查上游更新

页头「检查更新」：勾了技能就只查勾选的，没勾就查全部，逐个跑 `check_upstream`
（每个技能一次 `git ls-remote <remote> HEAD`），结果显示在「上游检查结果」弹窗里，
按 **有新版本 → 检查失败 → 未跟踪 → 已是最新** 排序，点任意一行直接打开那个技能。

看到「有新版本」后不用再跳出去：弹窗每行有「拉取更新」，底部有「全部更新（n）」。
更新时按远端地址分组，同一个仓库只 `git clone --depth 1` 一次；按目录名/技能名匹配
同名技能，`import_skill_folder(overwrite=true)` 覆盖，旧正文自动进版本历史；
覆盖后把 `[source.upstream]` 写回并重新 `check_upstream`，所以不会更新完反而变「未跟踪」。
覆盖导入会**合并标签**（旧标签保留 + 上游 frontmatter 新标签去重），不会把用户加的标签抹掉。

跟踪开关与上游地址在技能详情 →「来源与更新」里配置（`[source.upstream].watch = true` +
`mode = "git-scan"` + `remote`）。没开跟踪的技能会显示「未跟踪上游」，不会被当成检查失败。

截图：`docs/screenshots/upstream-check.png`（拉取入口）、`upstream-updated.png`（更新完成）。

## 版本时间轴与差异

技能详情右栏、提示词编辑器右栏的「版本时间轴」由两个开源组件拼起来，不再自己写：

| 部分 | 组件 | 为什么 |
|---|---|---|
| 竖线 / 节点 / 卡片 / 展开动画 | `react-vertical-timeline-component@4` | 竖轴这套几何与动画它已经调好，我们只覆盖颜色与间距 |
| 逐行与词级差异 | `react-diff-viewer-continued@4.4` | 行号、词级高亮、折叠上下文都有，颜色通过 `var(--…)` 传进去，跟随主题 |

配色不写死：`src/ahub/styles/version-timeline.css` 里所有颜色都取自 `tokens.css` 的
`--surface` / `--border` / `--success` / `--danger` 等，深浅主题自动跟随。

用法：技能详情 → 右栏时间轴 → 点某一版 → 「当前 / 上一版」切换对比基准 → 看差异 → 「恢复」。

## 来源机制（已关掉）

导入向导里的「来源确认」步骤**默认关闭**（`SOURCE_STEP_ENABLED = false`）：
步骤条只显示 探查 → 无法修复 → AI 修复 → 执行，进入向导时也不再预置来源，
导入执行拿到的是空表 —— 相当于不再给技能写来源归因。

保留代码与开关是为了能一键恢复；已存在条目上的 `source` 字段与标签**一律不动**
（删字段要写数据迁移，属于另一件事）。

## 预设（技能与 MCP 通用）

预设是「我常用的一组技能 / MCP 服务」，存在左侧预设栏（`PresetRail`），点名称即按成员筛选列表：

- **保存为预设**：批量模式勾选卡片后点「保存为预设」，把当前勾选存成一个命名集合。
  技能预设成员记技能目录名，MCP 预设成员记服务名（服务重建后 id 会变，名字仍是用户认得的那个）。
- **保存修改到预设**：选中某个预设后再勾选 / 取消卡片，工具栏会出现「保存修改到预设」，
  点一下就把当前勾选整体写回这个预设，不用进管理面板重新勾一遍。
- **管理**：预设栏右上角齿轮打开管理面板，可重命名、编辑成员（弹框内可搜索、
  批量勾选）、删除预设。成员芯片悬停出现两个删除动作：**×** 从预设移除（只动成员表）、
  **垃圾桶** 彻底删除技能 / MCP 服务本身（二次确认；后端会顺手把它从所有预设摘掉）。
- **删除自动清理**：删除技能或 MCP 服务时，后端（`presets::remove_skill` /
  `mcp_presets::remove_server`）会自动把它从所有预设成员里摘掉，不再留标灰的死条目。
- 预设选中即筛选，再点一次取消；点其他预设直接切换 —— 与标签的点击习惯一致。
  栏内不放描述文字。

存储：技能预设 `presets.json`、MCP 预设 `mcp-presets.json`（数据根目录下），写入走
「读-改-写 + 临时文件替换」，JSON 损坏直接报错而不是静默清空。

截图：`docs/screenshots/mcp-preset.png`（选中预设 + 批量工具栏上的「保存修改到预设」）。

## 按工具管理（批量配置）

技能与 MCP 都在页头有「批量配置」：选一个 AI 工具，集中管理它接了哪些东西。

- **已接入（置顶）**：列出该工具目录里已有的技能，显示接入时间；中枢里有更新时标
  「可更新」，可一键覆盖为中枢最新；「解绑」把技能从该工具目录移出。
- **中枢技能（可接入）**：中枢里还没接入该工具的技能，点「接入」复制过去。
  匹配规则与批量接入一致：目录名优先，frontmatter name 兜底（`skillHarness.ts`）。
- **搜索**：右上有搜索框，同时过滤「已接入」和「可接入」两段（技能按名字与描述、
  MCP 按名字与连接参数），关掉重开自动清空。
- 写入与移出复用后端 `apply_to_harness` / `remove_from_harness`（kind=skills），
  写入前自动快照备份；技能没有单文件配置，所以技能版没有 MCP 版的配置编辑器。

MCP 版见「批量配置」按钮（`HarnessConfigDialog`），技能版是 `SkillsConfigDialog`。

截图：`docs/screenshots/skills-harness-config.png`。

## 验证

- `npm run check:i18n`：ahub 那份词表（`src/ahub/i18n/index.ts`）zh/en 必须对齐，
  缺 key 会直接把 `skillImport.xxx` 画到界面上。
- 手测：打开收集面板 → 条目默认已勾选；点某条「详情」能看到 SKILL.md 与目录树；
  技能页进多选 → 选两条 → 批量停用 → 状态变灰且提示「成功 2 / 失败 0」。
- 手测工具维度：卡片底部能看到「已接入 Claude Code …」；点左栏「未接入工具」后只剩
  一个工具都没接的技能；多选两条 →「接入工具」→ 勾一个工具 → 执行 → 每个工具行显示
  ✓ 成功数，详情页头部出现该工具与最近同步日期。
- 手测预设：批量勾两条 →「保存为预设」→ 左栏出现新预设；选中它再改勾选 →
  「保存修改到预设」→ 成员数跟着变；删掉其中一个技能 / MCP 服务 → 预设成员数自动减一。
- 手测列表：技能页无「网格 / 分组」切换，卡片一行四张且无描述；
  生命周期非正常的技能显示中文状态（草稿等）；更新时间形如「2026年10月25日 18点59分」。
- 手测批量：批量模式按钮分两行（全选 / 打包导出 / 保存为预设 / 批量删除 +
  纳入技能管理 / 智能摘要 / 智能标签），无流水线 / 接入工具 / 批量启用停用。
- 手测批量配置：技能页点「批量配置」→ 左列列出支持技能目录的工具与数量；
  选一个工具 → 已接入 / 可接入两段与该工具目录实际内容一致；
  搜索框输入关键字 → 两段同时过滤、计数跟着变，清空恢复；
  「接入」一条 → 目录里出现副本，「解绑」→ 消失（都有自动备份）。
