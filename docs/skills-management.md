# 技能与 MCP 管理

技能（Skills）与 MCP 服务各自在「技能」「MCP」页管理，工具本身在「Harness 工具」页；
两边共用一套「从本机收集 → 应用到本机」的搬运逻辑。

## 收集面板

打开面板就会**扫描本机所有已知工具**（Claude Code / Codex CLI / Pi Agent /
OpenCode / WorkBuddy / CodeBuddy / DeepSeek），并把扫到的条目**默认全选**。

> 之前只有 MCP 默认全选、skills 留空勾选，于是「一键收集全部」看着像没激活。
> 现在两边同一套语义：能收的先勾上，用户只做减法。

## 技能市场（SkillHub / DeepSkill / GitHub）

「添加技能 → Git 仓库 → 技能市场」里有三个来源，卡片、勾选、批量安装共用同一套：

- **SkillHub**（腾讯）：官方 `api.skillhub.cn`，可按分类、来源（企业 / 社区 / clawhub）、热度排序，
  下载走 `api/v1/download?slug=`，交给 `import_skill_zip`（zip-slip / zip-bomb 防护与本地导入一致）；
- **DeepSkill**：`api/v1/skills/search/deep` 按场景分组返回，这里压平成一页卡片；
  安装走 `download/public?name=`，ZIP 或单文件 SKILL.md 都能吃；
- **GitHub**：仓库搜索（`q=<关键词> skill`，按星排序），安装时 `git clone --depth 1` 一次，
  把仓库里含 `SKILL.md` 的目录逐个装进来（限深 4、最多 20 个）。

装完顺手落上游指纹：GitHub 系写 `revision` + 子目录树 sha（`git-scan`），DeepSkill 写市场页地址（`web`），
所以从市场装进来的技能**一开始就可跟踪**，不用再走「补全上游」。

限额：单包 64 MB；GitHub 未登录搜索 10 次/分钟，超限会把 GitHub 的原话显示在市场弹窗里。

## 导入向导里的四件事

| 能力 | 说明 |
|---|---|
| 程序修复 | 目录名、`name` 字段、`SKILL.md` 大小写、描述缺失，先由程序修 |
| AI 修复 | 修不了的交给 AI 补描述（provider 不可用就保留原描述，记一条跳过） |
| **详情** | 每条候选右侧点「详情」→ 只读弹窗：**SKILL.md 正文 + 目录树**（复用 `SkillFileBrowser`），不写盘、不影响勾选 |
| 冲突处理 | 同名技能默认覆盖，可逐条取消（取消后同名冲突记为失败） |

## 导入后打标签

新建空白技能时标签在表单里选；从 ZIP / 文件夹 / Git 仓库 / 市场导入的条目，

## 批量检查上游更新

页头「检查更新」：勾了技能就只查勾选的，没勾就查全部，结果显示在「上游检查结果」弹窗里，
按 **有新版本 → 检查失败 → 未跟踪 → 已是最新** 排序，点任意一行直接打开那个技能。

### 怎么判定「有更新」

不再拿仓库 HEAD 当内容版本（那是「仓库动过」，不是「我的文件旧了」）。判定分三层：

1. **装的是哪一版**：安装/更新时把 `revision`（提交）、`subtree_path`（技能在仓库里的子目录）、
   `subtree_sha`（该子目录的树对象 sha）、`content_hash`（聚合指纹）以及
   `[source.upstream.files]`（逐文件 SHA-256，超过 200 个文件时只留聚合指纹）写进 `[source.upstream]`；
2. **远端现在是什么版本**：同一个 remote 一批技能只跑一次 `git ls-remote`，结果分发给该仓库下所有技能；
3. **仓库动了、我这一份动没动**：只有在 HEAD 变了且本地记了 `subtree_sha` 时，才做一次
   `git clone --filter=blob:none --no-checkout --depth 1`，用 `git rev-parse <head>:<path>` 比子树 sha。
   相等就记「仓库有新提交，本技能目录未变」，不算更新。

`remote_head` 只在**确认过这份内容就是最新**时才写回；发现更新却不改它，下一轮才不会把
「有新版本」误报成「已是最新」。老技能没有安装指纹时退回按仓库 HEAD 判定，并在 note 里写明。

AI 搜源（`skill_update_discover`）落库的 git 技能没有克隆过程：`apply` 时会补一次
`ls-remote` 把 `revision` 记上，但它没有子树指纹，所以仓库 HEAD 一动就算更新。

### 更新时怎么落地

按远端地址分组，同一个仓库只 `git clone --depth 1` 一次；按目录名/技能名匹配同名技能。
覆盖前先 `skill_update_preview` 对账：

- **内容一致** → 不覆盖，只把安装指纹记上（提示「与上游一致，已记录安装版本」）；
- **本地改过**（当前内容指纹 ≠ 安装时记的）→ 不碰，弹「本地改过，上游也变了」三选一：
  **保留我的 / 用上游覆盖 / 两个都留**（后者把上游另存为 `<目录名>-upstream`）。弹窗里列出
  改动/新增/删除的文件，点开任一文件就是**逐行差异**（`react-diff-viewer-continued`，与版本
  时间轴同一套视图），并按逐文件指纹标出「你改过」的那几个；
- **其余** → 覆盖，旧正文自动进版本历史，并把 revision + 子树 sha + 内容指纹重新落下。
  覆盖导入会**合并标签**（旧标签保留 + 上游 frontmatter 新标签去重）。

自动更新队列（「更新中心」）走同一条对账：本地改过的任务直接记为「已跳过」，不静默覆盖。

### 定时检查与角标

侧栏启动后 1 分钟跑一次后台检查，之后每 6 小时一次，只更新「N 个技能有上游更新」角标，
**不做自动应用**（自动应用默认关，目前没有开关）。手动「检查更新」会同时刷新角标。

### 上游补全（不用 AI 也能挂上）

很多技能装进来时只留了 `kind = "local"` 和一句已失效的临时目录路径，看着「未跟踪」，其实本地就有线索。
检查结果里对这类技能会给出候选地址和出处，点「补全上游」就挂上（只写 `[source.upstream]`，不动正文、不联网下载）：

| 证据 | 强度 | 例子 |
|---|---|---|
| 技能目录本身是 git 仓库，或 `[source].ref` 指向的目录在 git 里 | 强 | `本地 git 工作区` |
| `SKILL.md` frontmatter 里的 `homepage:` / `repository:` 是仓库地址 | 强 | `homepage: https://github.com/x/mono/tree/main/skills/x` |
| 文档里的安装说明（`npx skills add` / `git clone` / 「安装」「来源」段落里的仓库地址） | 强 | `README.md: npx skills add …` |
| `_skillhub_meta.json` 或 `_meta.json`（ownerId+slug）→ `skillhub search <slug> --json` 拿到 `repo_url` | 强（要联网，单行点才用） | `SkillHub 市场：diagram-builder` |
| 正文里顺手提到的链接（参考实现、示例 URL、徽章） | 弱 | 默认不挂，单行点「用这个」才采纳 |

判定顺序：本地 git 远端 → frontmatter/安装说明 → SkillHub 市场 → 弱证据。
**不会**往上找外层仓库根：开发时数据目录常落在某个项目仓库里（`src-tauri/target/debug/data/...`），
那样会把本项目认成所有技能的上游（实测 16/20 全错，所以这里刻意只认 `.git` 就在技能目录、或显式记录的导入来源）。

补全后第一次检查会显示「有新版本（未记录安装修订，按仓库 HEAD 判定）」——这是正常的：
点「拉取更新」，内容一致时只补安装指纹、不覆盖，从此以后就是按子树 sha 精确判定了。

跟踪开关与上游地址在技能详情 →「来源与更新」里配置（`[source.upstream].watch = true` +
`mode = "git-scan"` + `remote`）。没开跟踪的技能会显示「未跟踪上游」，不会被当成检查失败。
网页/书籍型来源没 commit，仍用正文 SHA-256 当版本指纹。

截图：`docs/screenshots/upstream-check.png`（拉取入口）、`upstream-updated.png`（更新完成）。

## 版本时间轴与差异

技能详情的「版本时间轴」收在工具栏「查看版本记录」弹框里（不再在右栏常驻）；提示词编辑器仍在右栏。
两处都由两个开源组件拼起来，不再自己写：

| 部分 | 组件 | 为什么 |
|---|---|---|
| 竖线 / 节点 / 卡片 / 展开动画 | `react-vertical-timeline-component@4` | 竖轴这套几何与动画它已经调好，我们只覆盖颜色与间距 |
| 逐行与词级差异 | `react-diff-viewer-continued@4.4` | 行号、词级高亮、折叠上下文都有，颜色通过 `var(--…)` 传进去，跟随主题 |

配色不写死：`src/ahub/styles/version-timeline.css` 里所有颜色都取自 `tokens.css` 的
`--surface` / `--border` / `--success` / `--danger` 等，深浅主题自动跟随。

用法：技能详情 → 工具栏「查看版本记录」→ 点某一版 → 默认看到**渲染后的预览**（差异视图那两列行号在窄栏里挤成一团，
所以不再默认给差异），要比对再切「差异」并在那里选「当前 / 上一版」基准 → 「恢复」
（恢复后弹框自动关闭、页签回到内容）。

## 技能详情的页签与工具栏

**内容页签**：SKILL.md 的 frontmatter（`name` / `description` / `metadata` …）不再拼进预览正文
（那样只会渲染成一坨 `key: value` 原文），改成预览区顶部一组**只读表单项**，一条属性一行。

**管理页签工具栏**：左边是三态切换（预览 / 编辑 / 分屏），右边一排动作，顺序固定：

| 位置 | 动作 | 说明 |
|---|---|---|
| 最左 | 生成摘要 / 重新生成 | 只在**已接入 AI** 时出现，与右边三个动作用一条竖线分隔 |
| 其后 | 暂存 | 只落盘，不产生版本记录 |
| 其后 | 发布 | 落盘 + 记一条版本；版本号一律按 L1（补丁）递增 |
| 最右 | 查看版本记录 | 打开版本时间轴弹框；某一版默认给**预览**，切「差异」才看逐行对比 |

发布不再有 L1~L4「变更级别」：**整个机制已删除** —— 前端不再传级别，
后端 `skill_save` / `release_skill_version` 一律按补丁递增（词条 `skills.saveLevel*` / `skills.levelL1..L4` 也删了）。

**详情头部**：标题下面是数据目录里的**全路径**（不再只显示目录名），点一下即复制路径并提示「已复制」；
后面跟内容长度，中文界面显示「22890 字符」（`skills.charCount`），不再是硬编码的 `chars`。

**审查页签按需出现**：只有这份技能还剩**未处置的审查发现**（`vetPending > 0`）时才显示，
处置完自动隐藏并退回内容页签；没纳入协议或从未体检的技能看不到它。
发现列表的严重程度用**四色徽标**（严重=红、高危=琥珀、中危=蓝、低危=灰，`sevMeta()` 决定 variant，
颜色仍只由 token 给）；每条右侧是「忽略 / 恢复」。底部「人工复核结论」的**批准 / 驳回靠右**，
左边留给「还差什么才能批准」的提示。

**右栏只留 AI 摘要**（320px 固定宽），版本时间轴不在右栏常驻。

### AI 摘要的生成时机

- **没接入 AI → 整个功能不出现**：右侧摘要栏不渲染，工具栏也没有生成按钮。
  「已接入」= 设置里有默认 AI 提供商且处于启用状态（与后端 `resolve_default` 的前置条件一致）。
- **进卡片自动生成一次**：打开详情、这份技能还没有摘要、本次会话没失败过 —— 三者同时满足才触发。
- **已生成就不主动重生成**：要更新点工具栏那个按钮（文案会变成「重新生成」）。
- **发布新版本后主动补一份**：`handleEditSave(true)` 成功、且详情读回来之后再生成，
  否则后到的详情会把刚写好的摘要覆盖掉。
- **生成失败就收起右栏**：失败的技能记进本次会话的失败集，不再自动重试，右侧摘要区不显示（正文拿满宽度）。

摘要本身仍写在 `.hub.json`，批量「智能摘要」走 `skill_generate_summary_batch`，行为不变。

## 来源机制（已关掉）

导入向导里的「来源确认」步骤**默认关闭**（`SOURCE_STEP_ENABLED = false`）：
步骤条只显示 探查 → 无法修复 → AI 修复 → 执行，进入向导时也不再预置来源，
导入执行拿到的是空表 —— 相当于不再给技能写来源归因。

保留代码与开关是为了能一键恢复；已存在条目上的 `source` 字段与标签**一律不动**
（删字段要写数据迁移，属于另一件事）。

## 预设（技能与 MCP 通用）

预设是「我常用的一组技能 / MCP 服务」，存在左侧预设栏（`PresetRail`），点名称即按成员筛选列表：

- **保存为预设**：单击卡片选中（可多张）后点「保存为预设」，把当前勾选存成一个命名集合。
  技能预设成员记技能目录名，MCP 预设成员记服务名（服务重建后 id 会变，名字仍是用户认得的那个）。
- **保存修改到预设**：选中某个预设后再勾选 / 取消卡片，工具栏会出现「保存修改到预设」，
  点一下就把当前勾选整体写回这个预设，不用进管理面板重新勾一遍。
- **管理**：预设栏右上角齿轮打开管理面板，可重命名、编辑成员（弹框内可搜索、
  批量勾选）、删除预设。成员芯片悬停出现两个删除动作：**×** 从预设移除（只动成员表）、
  **垃圾桶** 彻底删除技能 / MCP 服务本身（二次确认；后端会顺手把它从所有预设摘掉）。
- **删除自动清理**：删除技能或 MCP 服务时，后端（`presets::remove_skill` /
  `mcp_presets::remove_server`）会自动把它从所有预设成员里摘掉，不再留标灰的死条目。
- 预设选中即筛选，再点一次取消；点其他预设直接切换 —— 与标签的点击习惯一致。
  栏内不放描述文字。

存储：技能预设 `presets.json`、MCP 预设 `mcp-presets.json`（数据根目录下），写入走
「读-改-写 + 临时文件替换」，JSON 损坏直接报错而不是静默清空。

截图：`docs/screenshots/mcp-preset.png`（选中预设 + 批量工具栏上的「保存修改到预设」）。

## 按工具管理（批量配置）

技能与 MCP 都在页头有「批量配置」：选一个 AI 工具，集中管理它接了哪些东西。

- **已接入（置顶）**：列出该工具目录里已有的技能，显示接入时间；中枢里有更新时标
  「可更新」，可一键覆盖为中枢最新；「解绑」把技能从该工具目录移出。
- **中枢技能（可接入）**：中枢里还没接入该工具的技能，点「接入」复制过去。
  匹配规则与批量接入一致：目录名优先，frontmatter name 兜底（`skillHarness.ts`）。
- **搜索**：右上有搜索框，同时过滤「已接入」和「可接入」两段（技能按名字与描述、
  MCP 按名字与连接参数），关掉重开自动清空。
- 写入与移出复用后端 `apply_to_harness` / `remove_from_harness`（kind=skills），
  写入前自动快照备份；技能没有单文件配置，所以技能版没有 MCP 版的配置编辑器。

MCP 版见「批量配置」按钮（`HarnessConfigDialog`），技能版是 `SkillsConfigDialog`。

截图：`docs/screenshots/skills-harness-config.png`。

- `npm run check:i18n`：ahub 那份词表（`src/ahub/i18n/index.ts`）zh/en 必须对齐，
  缺 key 会直接把 `skillImport.xxx` 画到界面上。
- 手测：打开收集面板 → 条目默认已勾选；点某条「详情」能看到 SKILL.md 与目录树；
  技能页进多选 → 选两条 → 批量停用 → 状态变灰且提示「成功 2 / 失败 0」。
- 手测工具维度：卡片底部能看到「已接入 Claude Code …」；点左栏「未接入工具」后只剩
  一个工具都没接的技能；多选两条 →「接入工具」→ 勾一个工具 → 执行 → 每个工具行显示
  ✓ 成功数，详情页头部出现该工具与最近同步日期。
- 手测预设：批量勾两条 →「保存为预设」→ 左栏出现新预设；选中它再改勾选 →
  「保存修改到预设」→ 成员数跟着变；删掉其中一个技能 / MCP 服务 → 预设成员数自动减一。
- 手测列表：技能页无「网格 / 分组」切换，卡片一行三张且无描述；
  生命周期非正常的技能显示中文状态（草稿等）；卡片上只有「版本号 / 生命周期 /
  审查状态 / 标签」四类徽标 —— 不再有 STALE、资源、版本快照；
  右下三个按钮常驻（复制路径 / 打开目录 / 删除），点「复制路径」后剪贴板里是该技能
  目录的绝对路径并弹「已复制」；卡片时间是 `2026/12/02` 这种只到日的格式，
  hover 卡片时间能看到完整的年月日时分。
- 手测详情：内容页签预览顶部是一组只读元信息表单项（不再出现 `key: value` 原文）；
  管理页签工具栏依次是「生成摘要 ｜ 暂存 / 发布 / 查看版本记录」（未接入 AI 时没有生成摘要）；
  点「查看版本记录」在弹框里看时间轴并恢复；右栏只剩 AI 摘要；
  有待复核发现的技能才显示「审查」页签，处置完它自己消失、页签退回内容。
  顶部概览不再有「该技能已接入 SSEP…」那句话，改成「已接入管理」徽标；
  「来源与更新」「运行要求」两张卡片不再重复一遍自己的标题。
- 手测批量：卡片**单击 = 选中 / 取消，双击 = 打开详情**（技能与 MCP 两页同一套），
  所以没有「批量模式」开关了 —— 动作区就一行：左侧动作（没选中时禁用而不是消失），
  右侧是「已选 N」+ 一枚小一号的「全选所有 / 取消全选」（真的按总数全选，技能页数技能、MCP 页数服务）。
  批量删除红色常显。
  选中标识只有一种：卡片上的**勾选框**（有任一选中就整排出现，可以直接点它单选），
  卡片边框高亮永远和勾选框同时出现。
- 手测批量配置：技能页点「批量配置」→ 左列列出支持技能目录的工具与数量；
  选一个工具 → 已接入 / 可接入两段与该工具目录实际内容一致；
  搜索框输入关键字 → 两段同时过滤、计数跟着变，清空恢复；
  「接入」一条 → 目录里出现副本，「解绑」→ 消失（都有自动备份）。
