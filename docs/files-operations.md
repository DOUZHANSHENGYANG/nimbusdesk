# 盒内搜索、排序、删除风险与撤销

这一批能力是照着 [Pogget](https://github.com/EnderMo/PoggetCore)（Apache-2.0，Windows 桌面整理器）
的思路做的，实现按本仓库的约束改了形状：能在前端解掉的就不动 Rust，动 Rust 的只加一个只读命令。

## 盒内搜索

栅栏（桌面悬浮窗）只有一屏大小，条目一多滚轮翻页就不够用。标题栏的放大镜开一行输入框，
按**名称或路径**过滤当前盒子：

- 计数变成「命中/总数」，没有命中时显示「没有匹配的条目」而不是「这里还没有条目」
- 换搜索词或换排序会回到第一页 —— 否则可能停在一个已经不存在的页码上
- Esc 清空并收起搜索栏

实现：`src/features/files/fence.tsx` 里 `ordered → visible → pageItems` 三层推导，
键盘导航沿用原有的 `pageItems` 索引逻辑，不需要另写一套。

## 每盒排序

`FenceState.sortMode`：`manual`（手拖顺序）/ `name`（名称，`localeCompare` + `numeric`）/ `time`（最近添加）。

存在 `fences.json` 里，跟着盒子走。入口在标题栏 `⋯` 菜单里。

`time` 优先用文件自身的 `mtime`，没有才退回 `createdAt` —— 扫描进来的条目 `createdAt` 只是扫描时刻，
按它排等于「按扫描顺序排」，没有意义。

## 删除风险分级

`src/features/files/delete-risk.ts`（纯函数，7 条单测）。判定只看三件低成本能拿到的事：

| 条件 | 阈值 |
|---|---|
| 含文件夹 | 任意 -> 高风险（目录内容不可见，误删代价最大） |
| 总字节 | ≥ 100 MB -> 高风险 |
| 条目数 | ≥ 5 条 -> 高风险 |

低风险只给原来那句「会移到回收站」；高风险才补「里面的内容会整个进回收站」与合计体积。
**网页条目不动磁盘，不参与判定** —— 删五个书签不该被当成批量删除。

取不到大小时记成「未知」，不把未知当成「很小」。

## 撤销栈

`src/features/files/history.ts`（栈 + 纯函数）与 `undo.ts`（执行）。

| 操作 | 可撤销 | 撤销方式 |
|---|---|---|
| 重命名 | 是 | `rename_entry` 改回原名 |
| 移动（拖进/导入盒子） | 是 | `move_fence_entries` 搬回原目录 |
| 新建文件/文件夹 | 是 | 删掉当初建出来的那个空条目 |
| **删除** | **否** | 走系统回收站，撤销需要 shell 还原接口 |

删除**刻意不做假撤销**：与其做一个「撤销后其实找不回文件」的按钮，不如在 UI 上说清
「没有可撤销的操作（删除请到回收站还原）」。要真撤销删除，得先引入自有回收目录
（Pogget 的 `path3` 备份思路），那是另一件事。

细节：

- 栈上限 50（`HISTORY_LIMIT`），新的在最前
- 一次拖入多个文件用同一个 `groupId` 归并，撤销时整组出栈
- `sourceRetained`（目标写成但源没删掉）的条目不记移动 —— 撤销它会乱
- 快捷键 Ctrl/Cmd+Z，输入框内不拦截；工具条上不再放「撤销」按钮（快捷键足够，按钮还会和「添加条目」抢位置）

## 条目元信息缓存

`FileItem` 增加 `size` / `mtime` / `metaAt`，由新命令 `path_meta` 批量填充（`src-tauri/src/commands/fs.rs`）。

- 一天过期（`META_TTL`），每轮最多刷 200 条（`REFRESH_CHUNK`）
- 写回时内容没变就不产生新数组 —— 否则每次刷新都会触发一次整份持久化
- **目录不递归统计大小**（返回 `null`）：几百 GB 的目录递归一遍会让删除确认框卡好几秒
- 只在桌面端跑；浏览器夹具里 `inTauri` 为假，直接跳过

## 验证

```powershell
npm run verify                    # 含 delete-risk 7 条、meta-cache 5 条、history 4 条
npm run check:files-list          # 浏览器回归（需 dev server 17800）
```

手测：删一个几 KB 的文件（确认框只有一句话）→ 删一个文件夹（多一句警告）→
重命名一个条目后按 Ctrl+Z（名字改回来）→ 往盒子里拖一个文件后按 Ctrl+Z（文件回到原目录）。

## 收纳盒的品类色（固定，不可改）

三种收纳盒各有一条固定色，写进 `src/styles/tokens.css` 的 `--kind-shortcut / --kind-storage / --kind-mapped`（明暗两套主题各一组）：快捷=蓝、存储=黄、映射=橙。

- 墙上方块只画**一圈 1.5px 品类色描边**，盒面保持中性玻璃；顶色带、品类色底色与品类图标都已撤掉；
- 数量徽标用同一个品类色，盒子不引入第四种颜色；
- 点开盒子后，浮层标题旁有一颗**只读的种类标签**（同色），浮层描边也取同一条色；
- 快速面板、桌面栅栏读同一组 token，同一个盒子在任何界面都是同一个颜色；
- 用户不能改种类和颜色：建盒时选定，之后没有切换入口（外观弹窗只留版式/字号这类偏好）。

旧的 `--chart-*` 是给图表用的（数据系列），不再兼任收纳盒品类色，避免"数据色"和"身份色"混用。
