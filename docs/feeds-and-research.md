# 资讯订阅与信息调研

两件独立的事，共用一个「不依赖模型」的 Rust 检索层：

- **资讯订阅**（`/tools/feeds`）：定期把 RSS、搜索结果、社区帖子、网页变化收进本地，按源浏览。
- **信息调研**（`/tools/research`）：给一个主题，检索 → 抓正文 → 抽断言 → 合成带来源的简报并存盘。

## 资讯订阅

### 五种源

| 类型 | 要填的字段 | 采集方式 |
| --- | --- | --- |
| RSS / Atom | `url` | 直接抓取并解析（RSS 2.0 / Atom，支持 `content:encoded`） |
| 搜索 | `queries[]` | 本机 SearXNG（默认 `http://127.0.0.1:8888`，`format=json`） |
| 中文社区 | `queries[]`、可选 `sites`（默认 `zhihu,xiaohongshu,douyin`） | 逐站点调 `opencli <site> search <词> --format json` |
| 网页变化 | `url`，可选 `title` | 抓正文后与上一版比对，变了才产出一条，并记录新增行 |
| opencli | `site`、`command`（默认 `search`）、`query` | `opencli <site> <command> [query] --limit 20 --format json` |

每个源还有刷新间隔（分钟，钳在 5–1440）。到期判定在后台线程里做：每 60 秒检查一次，
距上次运行超过间隔就采集，完成后广播 `feeds://updated`，界面只替换该源的缓存。

### 界面行为

- 整页分左右两列：左列从顶到底放「收藏 / 订阅源」，右列上面是工具栏（刷新全部 / 网络 / 管理订阅源 / 添加源），下面是列表与正文。
- 「订阅源」是一条列表，自建源与内置热榜（GitHub Trending / Hacker News / Solidot / 少数派 / 知乎热榜 / V2EX）混排：内置的只是默认值。拖动（或聚焦后 `Alt+↑/↓`）调整顺序，拖动时目标行上下会画出插入线；顺序存在本机（`feed-order`）。「管理订阅源」对话框里同样可以拖。
- 自建源可编辑、删除；内置源可「移除」——管理订阅源对话框里的「恢复默认来源」把它们和顺序一起还原。
- 右侧再分「列表 + 正文」：列表 360px（没选条目时占满），正文占剩余宽度；窄于 1280px 时正文改成弹窗。
- 条目首次点开即标为已读；标题栏的「全部已读」一次清空当前源。
- 「收藏」同时写本地收藏夹与条目的 `starred`（`starred` 的条目不会被条目上限裁掉）。
- 管理订阅源对话框里：编辑、删除、**导入 OPML**（选文件，Rust 读文件并解析）。

### 数据

`<数据目录>/modules/feeds/state.json`，结构见 `src-tauri/src/feeds/mod.rs` 的 `FeedState`：

- `sources[]`：`id/kind/name/config/enabled/intervalMinutes/sortOrder/lastRunAt/lastStatus/lastError/lastCount`
- `items[]`：按 `urlHash` 去重（去 `utm_*`、锚点、尾斜杠），上限 2000 条，`starred` 永不裁剪

旧版本存在 localStorage 里的 RSS 订阅（`custom-feeds`）会在首次加载时自动迁移成 `rss` 源，然后清空。

**没有移植**：邮件日报（需要 SMTP 凭据）。AI 摘要沿用页面已有的「AI 速览 / AI 摘要」。

## 信息调研

版式对齐 ShiCang 的调研页：上面一张提问卡，下面左「调研记录」右「任务队列 + 历史报告」。

提问卡：多行输入（`Ctrl/⌘ + Enter` 开始）、深度分段、渠道复选（默认全选）、右侧「开始调研」。空状态给标题和说明。

| 深度 | 子问题 | 每词条数 | 来源上限 | 每源断言 |
| --- | --- | --- | --- | --- |
| 快速 | 3 | 4 | 6 | 3 |
| 标准 | 4 | 5 | 10 | 4 |
| 深入 | 6 | 6 | 16 | 5 |

渠道：`web`（SearXNG）、`cn-social`（B 站/知乎/小红书/抖音，经 opencli）、`global`（reddit/hackernews/twitter/youtube，经 opencli）、`repo`（GitHub 仓库检索，走 REST；有 `GITHUB_TOKEN` 环境变量就带上）。

**选中就一定检索过**：规划没给该渠道检索词时回落到子问题，再回落到主题本身。

流水线（全部由前端驱动，模型调用走 `chatWithProvider`）：

1. **规划**：让模型拆子问题并给检索词，失败退回「主题本身当查询」；
2. **检索**：四个渠道**并发**各调一次 `research_search`，单渠道失败只记一条警告；
3. **抓正文**：`research_fetch` 抓 HTML 转纯文本，`≥300` 字才算可用，单篇截到 20000 字；
4. **抽断言**：逐源让模型输出 `{claim, quote}`，`quote` 前 20 字必须在正文里出现才算「已核对」；最多三个源同时抽，结果按来源编号归并；
5. **合成**：只允许用抽到的断言写简报（结论先行、每条带 `[编号]`、单源标「（单源，待验证）」）；
6. **存档**：报告含 frontmatter、证据表、来源表、方法段。

### 队列与过程

运行状态在模块级 store（`src/features/research/store.ts`）：切页面不中断，回来接着看。

- **队列**：每次「开始调研」入队，最多同时跑 2 个；右侧列出全部任务（状态点、当前步、耗时），排队/暂停的任务可以「置顶」「暂停 / 继续」。
- **记录**：左边按对话式回放——问题气泡、五阶段进度（规划 / 检索 / 抓正文 / 抽证据 / 合成）、可折叠的过程（子问题与检索词、各渠道前几条结果链接、抓取清单含字数与 OK/摘要、逐篇断言数、完成或失败），最后是报告正文。
- **取消**：「取消」先确认，再立即停；正在发出的请求让它自然结束，过程记录保留。
- **队列持久化**：任务列表写本机（`research-jobs`）。关窗口/刷新后，未跑完的任务标成「已中断」而不是继续显示运行，已完成的任务连事件一起保留；磁盘上另有已生成的报告（右侧「历史报告」可读）。

### 报告目录

默认存 `<数据目录>/modules/research/YYYY-MM-DD-<slug>-<hash>.md`，同名 `.json` 存 meta；左栏历史可读、可删。

设置 → 系统 → 数据 → 「调研报告目录」可以换到任意绝对路径（选择目录 / 恢复默认），改完即时生效：列表、读取、删除、新报告都走新目录，旧目录里的文件不会搬。

## 验证

```powershell
npm run check:feeds      # 订阅源合并、缓存与运行时（含失效/重试/并发）
npm run check:research   # 规划 JSON 解析、来源去重与跨渠道轮转
npm run check:rust       # 含 feeds/html、feeds/store、feeds/collect、research 的单测
npm run tauri dev        # 真机：添加 RSS 源 → 刷新 → 已读/收藏 → 全部已读
```

调研的真机验证需要先配置好 AI 提供商，并确认 SearXNG 在 `127.0.0.1:8888` 可访问。

## 已知边界

- `page` 源没有浏览器选器，配置里的 `selector` 会被忽略，只按整页正文变化判定。
- opencli 子进程没有超时；卡死会占住一个采集线程（代码里标了 `shortcut:`）。
- SearXNG 单次检索可能 8 秒以上，超时给到 45 秒。
